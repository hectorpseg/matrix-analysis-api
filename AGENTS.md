# Implementation rules
- Readable, well-structured code. Descriptive variable, function and file names, following each language's conventions.
- Apply KISS, YAGNI and DRY: simplest solution that meets the requirement; no abstractions, layers, dependencies or config "just in case"; no duplicated logic.
- Short, to-the-point comments that state what problem each function or non-obvious block solves. Do not comment the obvious.
- Never use em dashes anywhere (code, comments, docs, messages). Use commas, semicolons or simple hyphens (-).
- Scope: do only what the current prompt asks. Do not touch other files or add features.
- Do not add a dependency without justifying it in one line first.
- Code, comments and JSON fields in English. README and UI text in Spanish.
- When done, list the files touched and the commands to verify. Do not continue to the next phase.
